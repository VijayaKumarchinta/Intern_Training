# Order and Sales Management Application

## 1. Project Overview

The Order and Sales Management Application is a traditional web application designed to manage customer orders and sales operations for an e-commerce business.

The application uses the **Online Store Orders Dataset** as its reference for the data fields and business requirements.

The technology stack consists of:

- **Frontend:** Vue.js
- **Backend:** Flask
- **Database:** PostgreSQL

The application connects to the existing PostgreSQL database `machine_monitor_db` and schema `Order_sales_schema`. It will not create or modify database objects.

## 2. Dataset Reference

**Dataset:** Online Store Orders Dataset  
**Source:** Excelx.com — Sample Sales Data Excel Download  
**Dataset size:** Approximately 1,200 records

The dataset contains the following fields:

| Column | Purpose |
|---|---|
| OrderID | Identifies an order |
| Date | Records the order date |
| CustomerID | Identifies the customer |
| Product | Identifies the purchased product |
| Quantity | Records the quantity ordered |
| UnitPrice | Records the unit price |
| ShippingAddress | Records the delivery address |
| PaymentMethod | Identifies the payment method |
| OrderStatus | Tracks the order status |
| TrackingNumber | Supports delivery tracking |
| ItemsInCart | Provides additional cart information |
| CouponCode | Identifies an applied coupon |
| ReferralSource | Records the order's referral source |
| TotalPrice | Records the order total |

The dataset is the reference for the application requirements. Its actual values and column types must be inspected before data is mapped to PostgreSQL.

## 4. Application Requirements

### 4.1 Customer Order Management

Users can create, view, and search customer orders.

The application uses order identifiers, customer identifiers, products, quantities, prices, and other available order details.

### 4.2 Validate Order Details

Flask validates incoming requests before processing them.

Validation includes:
- Required fields are present.
- Order and customer identifiers are valid.
- Quantities are positive.
- Prices are non-negative.
- Product and order details are consistent.
- Order status values are permitted.

### 4.3 Calculate Order Totals

The backend calculates order totals rather than trusting totals submitted by the frontend.

For an order containing one product:

`Total = Quantity × UnitPrice`

For an order containing multiple products:

`Subtotal = Sum of all line totals`

If discounts, coupons, or shipping charges affect the final amount, their calculation rules must be defined consistently with the available dataset and business requirements.

### 4.4 Track Order Status

The application displays and updates order statuses according to the permitted business rules.

Example statuses include Pending, Processing, Shipped, Delivered, and Cancelled. The actual supported values must be verified against the data and application requirements.

### 4.5 Identify Duplicate Orders

The application checks whether an order has already been processed.

The primary check should use a stable order identifier such as `OrderID`, if it uniquely identifies an order in the dataset and existing database.

Repeated API submissions should not create duplicate orders. Multiple product rows belonging to the same order must not automatically be treated as duplicate orders.

### 4.6 Generate Product-Wise Sales Reports

The report summarizes sales by product.

Expected information:
- Product name or identifier
- Total quantity sold
- Total sales amount

### 4.7 Generate Date-Wise Sales Reports

The report summarizes sales for a selected date range.

Expected information:
- Order date
- Number of qualifying orders
- Total sales amount

Both reports are generated by Flask using SQL aggregation against the existing PostgreSQL data.

## 6. Database Connection

The application connects to the existing database using environment variables.

Example configuration:

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_NAME=machine_monitor_db
DB_SCHEMA=Order_sales_schema
DB_USER=your_database_username
DB_PASSWORD=your_database_password
```

The actual connection settings must match the PostgreSQL server configuration.

### Database restrictions

- Do not create a database or schema.
- Do not create, alter, or drop tables.
- Do not run migrations.
- Use only existing tables and columns.
- Report missing tables, columns, or permissions instead of attempting to modify the database.

The actual schema must be inspected before implementing database queries.

## 7. API Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/customers` | List all customers |
| GET | `/api/customers/<customer_id>` | Get a customer by ID |
| POST | `/api/customers` | Create a new customer |
| GET | `/api/products` | List all products |
| GET | `/api/products/<product_id>` | Get a product by ID |
| POST | `/api/products` | Create a new product |
| GET | `/api/orders` | List all orders |
| GET | `/api/orders/<order_id>` | Get an order by ID |
| POST | `/api/orders` | Create a new order |
| PUT | `/api/orders/<order_id>/status` | Update order status |
| GET | `/api/reports/product-sales` | Product-wise sales report |
| GET | `/api/reports/date-sales` | Date-wise sales report |

Duplicate orders are prevented by checking if an OrderID already exists.

## 9. Testing

The application will be tested for:

- Valid and invalid order requests.
- Incorrect quantities and prices.
- Correct order-total calculations.
- Duplicate order submissions.
- Valid and invalid status changes.
- Product-wise sales aggregation.
- Date-wise sales aggregation.
- Database connection failures.
- Missing schema objects and insufficient permissions.

## 10. Expected Outcome

The application will provide a simple web interface for managing customer orders, validating order details, calculating totals, tracking order statuses, detecting duplicate submissions, and generating product-wise and date-wise sales reports.

It will use Vue.js, Flask, and the existing PostgreSQL database, with the Online Store Orders Dataset serving as the reference for the required business functionality.

No database or schema objects will be created or modified by the application.
